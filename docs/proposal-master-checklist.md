# 사업수주형 제안서 작성 Master Checklist & 교육 지침서

> 적용 사례: 「2026 청년취업사관학교 8개 캠퍼스 교육(수료)생 일자리 연계 지원 프로그램 운영용역」(2026-122)

## 이 지침서의 목적

이 문서의 목적은 “제안서를 다 썼는가”가 아니라 **평가위원이 근거를 확인하고 점수를 줄 수 있는가**를 판단하는 데 있다. 기존 Master Checklist의 12개 핵심 구조를 유지하면서 각 항목을 교육목표, 평가위원 관점, 작성원칙, 좋은/나쁜 예시, 실무 적용 포인트, 증빙자료 기준, PT/Q&A 연결 포인트로 확장하였다.

### 이 사업에서 반드시 기억할 숫자

| 구분 | 평가·수행 기준 |
|---|---:|
| 기술역량 | 90점(정량 20점 + 정성 70점) |
| 가격 | 10점 |
| 정성: 과업이해도 | 10점 |
| 정성: 잡코디 배치·운영·관리 | 15점 |
| 정성: 채용기업 발굴·취업지원 | 25점 |
| 정성: 수행인력 | 10점 |
| 정성: 과업관리능력 | 10점 |
| 목표 취업률 | 2026년·2027년 전 과정 및 각 담당 캠퍼스 80% 이상 |
| 잡코디 | 8개 캠퍼스 총 13명 |
| 사업운영인력 | 3명(잡코디 제외) |
| 채용수요 연계 | 월 30건(면접 기준) |
| 매칭데이 | 통합 2회, 담당 캠퍼스별 2회 이상 |
| 제안서 / PT | 표지 포함 50쪽 / 30쪽 이내 |
| 발표 / Q&A | PM 발표 10분 / 질의응답 15분 내외 |

### 평가위원이 점수를 주는 기본 문장

> 문제·요구사항 → 제안사의 해석 → 실행방법 → 담당자 → 일정 → KPI → Evidence → 기대성과

위 연결고리 중 하나가 빠지면 좋은 아이디어일 수는 있어도 고득점 제안으로 보기 어렵다. 특히 이 RFP는 평가항목의 근거자료가 없으면 “해당 사항 없음”으로, “가능할 것이다”, “고려하고 있다”와 같은 모호한 표현은 “불가능”으로 간주한다.

## 1. RFP 분석 단계

### 교육목표

- 공고문, 제안요청서, 과업지시서, 서식에서 요구사항·평가기준·제출조건을 빠짐없이 추출한다.
- 배점이 높은 항목에 작성시간과 페이지를 우선 배분한다.

### 평가위원 관점

평가위원은 제안사가 사업명만 이해했는지가 아니라 발주기관의 성과목표, 캠퍼스별 차이, 이해관계자, 실행 제약을 한 체계로 해석했는지를 본다. 본 사업의 중심은 프로그램 개최 자체가 아니라 **교육(수료)생의 실질 취업과 80% 이상 취업률 달성**이다.

### 작성원칙

1. RFP 문장을 `필수`, `평가`, `정량`, `제출`, `금지`, `계약상 의무`로 분류한다.
2. 정성평가 70점의 세부 질문을 모두 제안서 목차와 페이지에 매핑한다.
3. 과업지시서의 달성기준을 KPI 초깃값으로 사용한다.
4. 질문이 없는 일반 회사소개보다 평가질문에 직접 답하는 페이지를 먼저 확보한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “취업률 80% 달성을 최종 Outcome으로 두고, 8개 캠퍼스 전 과정 분석 → 취업가능 직무 도출 → 실수요 기업 확보 → 면접 → 입사 → 취업증빙의 퍼널로 설계한다.”

**나쁜 예시**: “당사는 풍부한 노하우로 청년의 취업을 적극 지원하겠다.”

### 실무 적용 포인트

- [ ] 사업의 최종 정책목표와 성과목표를 한 문장으로 정의했는가?
- [ ] 발주기관이 해결하려는 핵심 문제를 3개 이내로 정리했는가?
- [ ] 정량·정성·가격 배점을 분리하고 정성항목을 배점순으로 재정렬했는가?
- [ ] 평가위원의 세부 질문을 누락 없이 추출했는가?
- [ ] `중요`, `필수`, `반드시`, `불가`, `제외` 표현을 별도 관리하는가?
- [ ] 제안요청서와 과업지시서를 교차 검토했는가?
- [ ] 실격·감점·불인정 조건을 별도 Gate로 만들었는가?

### 증빙자료 기준

- 요구사항 추적표에 `RFP 위치 / 요구사항 / 담당자 / 제안서 페이지 / 증빙 페이지 / 완료상태`를 기록한다.
- 해석이 필요한 요구사항은 추정으로 확정하지 말고 공식 질의 결과를 남긴다.

### PT/Q&A 연결 포인트

- 첫 1분 안에 “이 사업의 성공을 무엇으로 정의했는가”를 말할 수 있어야 한다.
- 예상 질문: “가장 큰 사업 리스크는 무엇이며, 왜 그렇게 판단했습니까?”

## 2. 평가항목 → 제안서 매핑

### 교육목표

평가표의 모든 질문이 제안서의 특정 페이지, KPI, 증빙과 연결되도록 한다.

### 평가위원 관점

평가위원은 제한된 시간에 평가표 순서대로 근거를 찾는다. 좋은 내용도 찾기 어렵거나 다른 장에 흩어져 있으면 점수화되기 어렵다.

### 작성원칙

각 평가항목마다 아래 7문항에 답한다.

- [ ] 평가위원이 확인하려는 것은 무엇인가?
- [ ] 발주기관의 문제는 무엇인가?
- [ ] 우리의 해결방법은 무엇인가?
- [ ] 경쟁사와 다른 실행 자산은 무엇인가?
- [ ] 누가, 언제, 어떤 절차로 수행하는가?
- [ ] 어떤 수치로 성과를 관리하는가?
- [ ] 이를 입증할 Evidence는 무엇인가?

### 좋은 예시 / 나쁜 예시

**좋은 예시**: 평가항목 `잡코디 상담 품질` → 본문 18쪽 운영 프로세스 → 부록 E-12 상담 매뉴얼 → PT 7쪽 → 예상 질문 Q-06.

**나쁜 예시**: “상담 품질을 철저히 관리한다”는 문장만 여러 장에서 반복한다.

### 실무 적용 포인트

- [ ] 평가항목마다 문서 오너를 1명 지정했는가?
- [ ] 배점에 비례해 페이지·작성시간·PT 시간을 배분했는가?
- [ ] 같은 수치가 본문·표·PT·견적서에서 일치하는가?
- [ ] 평가표의 표현을 목차와 페이지 제목에 활용했는가?

### 증빙자료 기준

Evidence Map은 최소 `주장 ID / 주장 / 평가항목 / 증빙명 / 기준일 / 보유자 / 본문·부록 페이지 / 개인정보 처리`를 포함한다.

### PT/Q&A 연결 포인트

- PT 목차도 평가표 순서를 따른다.
- 질문을 받으면 `결론 → 수치 → 실행방법 → 근거 페이지` 순으로 답한다.

## 3. 과업 이해도 체크 — 10점

### 교육목표

- 사업목적을 복사하지 않고 발주기관 관점의 문제와 성공조건으로 재해석한다.
- 8개 캠퍼스, 교육과정, 교육(수료)생, 교육파트너의 차이를 전략과 목표에 반영한다.

### 평가위원 관점

평가위원은 다음을 묻는다.

1. 사업의 목적·취지·내용·특성을 정확히 이해했는가?
2. 캠퍼스별 목표 취업률은 교육생 수와 운영과정을 근거로 제시했는가?
3. 80% 이상 취업률을 달성할 만큼 계획이 구체적이고 현실적인가?
4. 청년취업사관학교의 “일자리 파트너” 역할을 이해했는가?
5. 평균 취업률 80%를 위한 현실적인 방안과 아이디어가 있는가?

### 작성원칙

1. 사업목표를 `행사 횟수`가 아니라 `취업성과`로 표현한다.
2. 캠퍼스별 `과정·교육생 규모·수료시기·취업가능 직무·채용시장·기존 취업률·격차`를 분석한다.
3. 병목을 정의하고 전략과 직접 연결한다.
4. 목표 → 전략 → 세부과업 → KPI → 증빙을 한 장에서 추적 가능하게 만든다.
5. 제안사의 장점보다 이 사업에서 그 장점이 필요한 이유를 먼저 쓴다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “도봉 캠퍼스 A과정은 수료시점과 하반기 채용시즌의 간격이 짧으므로 입과 4주 내 직무진단을 완료하고, 수료 8주 전 수요확인 기업 20개와 사전매칭을 시작한다. 목표는 취업률 82%, 3개월 내 입사 70%다.”

**나쁜 예시**: “모든 캠퍼스에 동일한 우수 프로그램을 적용하여 취업률을 향상한다.”

### 실무 적용 포인트

- [ ] 사업 대상자의 특성과 취업 장애요인을 분석했는가?
- [ ] 8개 캠퍼스 전 과정의 취업가능 직무를 도출했는가?
- [ ] 캠퍼스별 목표 취업률의 산식과 모수를 제시했는가?
- [ ] 기존 방식의 병목과 우선 개선과제를 제시했는가?
- [ ] 2026년과 2027년의 목표·운영 차이를 반영했는가?
- [ ] 이해관계자별 역할과 의사결정 지점을 표시했는가?

### 증빙자료 기준

- 캠퍼스별 과정 분석표, 교육생 규모와 수료일정, 채용시장 자료, 유사사업 성과를 사용한다.
- 외부 통계는 출처와 기준일을 표시한다.
- 개별 교육파트너나 캠퍼스 담당자에게 직접 접촉해 정보를 얻어서는 안 되며, 문의는 발주처 공식 경로를 사용한다.

### PT/Q&A 연결 포인트

- PT에서는 캠퍼스별 차이와 공통 운영모델을 한 장에 대비한다.
- 예상 질문: “80% 목표의 현실적 근거는 무엇입니까?”, “가장 취업이 어려운 과정은 무엇이고 어떻게 대응합니까?”
- 답변에는 산식, 선행지표, 미달 시 조치가 포함되어야 한다.

## 4. 실행계획 체크 — 잡코디 운영 15점

### 교육목표

13명의 잡코디가 입과부터 집중 취업지원기간까지 상담에 몰입하고, 상담데이터가 실제 채용연계로 이어지는 운영체계를 설계한다.

### 평가위원 관점

평가위원은 채용·배치, 공백 대응, 상담 절차와 매뉴얼, 데이터 관리, 상담 품질, 역량강화, 취업독려, 취업증빙, 법적·행정적 적합성, 업무 몰입도를 본다. 잡코디는 주 5일·8시간, 주 3일 캠퍼스·주 2일 재택근무가 기본이며 발주부서 과업 외 추가업무나 타 업무 겸임을 제안할 수 없다.

### 작성원칙

1. `선발 → 교육 → 배치 → 상담 → 데이터 기록 → 사례회의 → 채용연계 → 취업증빙 → 성과관리` 전 과정을 제시한다.
2. 상담 단계별 완료조건, 기록 필드, SLA, 책임자를 정한다.
3. 13명 배치표에 캠퍼스별 교육생 수·과정·피크시기를 반영한다.
4. 결원 발생 시 인지, 보고, 임시대응, 대체투입 기한을 명시한다.
5. 품질관리는 단순 교육 횟수가 아니라 상담기록 표본검수, 코칭, 재교육, 개선확인으로 설계한다.
6. 취업독려 이벤트는 500명 기준을 반영하되 김영란법 등 법적·행정적 적합성을 사전 검토한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “상담 후 24시간 내 필수 12개 필드를 입력하고, 팀장이 매주 표본 10%를 정확성·실행과제·후속일정 기준으로 검수한다. 80점 미만은 48시간 내 보완하고 월 1회 사례 코칭에 반영한다.”

**나쁜 예시**: “월 1회 교육을 통해 상담 품질을 강화하며, 필요 시 잡코디가 1:1 서류 컨설팅과 행사 운영도 지원한다.” 후자는 별도 전문가가 수행해야 할 1:1 구직서류 프로그램을 잡코디 추가업무로 제안한 오류다.

### 실무 적용 포인트

- [ ] 13명 선발기준과 캠퍼스별 배정근거가 있는가?
- [ ] 입과부터 집중 취업지원기간까지 끊기지 않는 상담 여정을 제시했는가?
- [ ] 상담 단계별 KPI와 데이터 정의가 있는가?
- [ ] 월 1회 상담데이터·성과·근태 관리 절차가 있는가?
- [ ] 총 3회 이상 역량강화 교육의 주제와 사후평가가 있는가?
- [ ] 잡코디 공백 시 대체인력 Pool과 투입기한이 있는가?
- [ ] 잡코디가 상담에 100% 몰입하도록 추가·겸임업무를 차단했는가?
- [ ] 취업독려와 증빙확보 방안이 개인정보·청탁금지 등 법규에 맞는가?

### 증빙자료 기준

- 실제 사용 가능한 선발기준표, 직무기술서, 배치표, 상담 매뉴얼, 상담기록 양식, 품질평가표, 교육교안, 대체인력 명단을 제시한다.
- 시스템 화면은 데모 데이터로 개인정보를 제거하고, 화면만이 아니라 누가 어떤 주기로 사용하는지도 설명한다.

### PT/Q&A 연결 포인트

- PT에서 교육생 1명의 입과부터 입사까지 상담 여정을 시연한다.
- 예상 질문: “잡코디 1인당 적정 관리인원은?”, “결원 2명이 동시에 발생하면?”, “상담 품질 저하를 어떻게 조기에 발견합니까?”
- 답변에는 기준 수치, 경보 조건, 대체투입 시간, 책임자를 포함한다.

## 5. 실현가능성 체크

### 교육목표

제안한 인력, 기업, 전문가, 시스템, 일정, 예산이 계약 즉시 실제 가동 가능한지 검증한다.

### 평가위원 관점

평가위원은 화려한 아이디어보다 “누가 이미 확보되어 있고, 어떤 근거로 언제부터 투입되는가”를 본다. 단순 DB, 광고·홍보를 통한 향후 모집, 유명인 이름만 제시하는 것은 실수요 기업이나 가용 전문가의 증거가 아니다.

### 작성원칙

- 현재 보유, 확정, 조건부, 향후 확보를 구분한다.
- 신규 아이디어에는 담당자·일정·예산·KPI·리스크·대안을 붙인다.
- 제안사항을 일정표와 견적서에 동시에 반영한다.
- “협의 예정”은 협의 주체, 시점, 의사결정 기준, 불성립 시 대안을 함께 쓴다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “현직 HR 전문가 18명 중 12명의 참여의향과 가능시간을 확인했으며, 직무별 배정표와 대체 Pool 6명을 부록 E-21에 제시한다.”

**나쁜 예시**: “업계 최고 전문가를 섭외할 예정이다.”

### 실무 적용 포인트

- [ ] 실제 보유하지 않은 자원이나 인력을 확정형으로 쓰지 않았는가?
- [ ] 협력기업·전문가의 투입 가능성을 기준일 현재 확인했는가?
- [ ] 과거 사례는 결과 수치와 재현조건까지 제시했는가?
- [ ] 과업기간과 예산 내 실행 가능한가?
- [ ] 목표 미달과 자원 미확보 시 Plan B가 있는가?

### 증빙자료 기준

참여의향서, 최근 협업실적, 담당자 확인기록, 전문가 이력과 가용시간, 시스템 권한·화면, 견적 산출근거를 사용한다. 의향서는 계약이나 채용수요 확약과 동일하게 표현하지 않는다.

### PT/Q&A 연결 포인트

- 예상 질문: “오늘 계약하면 내일 무엇부터 가동됩니까?”, “확보됐다고 말한 기업·전문가 중 확정된 수는 몇입니까?”
- 숫자는 `전체 Pool / 연락 가능 / 수요 확인 / 참여 확정`으로 구분해 답한다.

## 6. 기업·기관 네트워크 제안 체크 — 채용기업 발굴·취업지원 25점

### 교육목표

- 8개 캠퍼스 전 과정과 실제 채용직무를 연결한다.
- 기업 수가 아니라 실수요, 채용 TO, 면접, 최종입사로 이어지는 Funnel을 설계한다.
- 1:1 구직서류 완성 프로그램과 매칭데이를 실질 취업성과에 연결한다.

### 평가위원 관점

가장 높은 25점 항목이다. 평가위원은 최근 채용 트렌드, 양질의 취업처, 현재 가용 기업과 채용수요, 캠퍼스별 적합성, 매칭데이 실행력, 구직서류 프로그램의 실효성, 참여율, 실제 가용 전문가를 본다. 단순 DB·플랫폼·회원사·친분·광고홍보는 채용수요 발굴로 인정하지 않는다.

### 작성원칙

1. 전 과정 분석을 통해 과정별 취업가능 직무를 도출한다.
2. 기업을 `보유 DB → 접촉 가능 → 수요 확인 → TO 확인 → 추천 동의 → 면접 확정 → 채용` 단계로 구분한다.
3. 직무, 근무지, 고용형태, 처우, 경력조건, 채용시기, TO를 확인한다.
4. 캠퍼스별 맞춤 채용정보를 주 1회 제공하고, 월 30건 면접 연계를 관리한다.
5. 통합 매칭데이 2회, 담당 캠퍼스별 2회 이상을 설계한다.
6. 통합 매칭데이는 면접부스 30개 내외, 체험 프로그램 10개 부스 내외를 기준으로 하며 사전 서류전형 후 면접희망 기업·교육생 중심으로 운영한다.
7. KPI는 발굴기업, 채용 TO, 서류신청, 면접연계, 최종입사를 각각 제시한다.
8. 1:1 구직서류 완성 프로그램은 잡코디 상담과 별개로 현직자·HR 전문 컨설턴트가 운영하며 교육생 500명 기준으로 설계한다.
9. 단순 경품·프로모션이 아닌 진단, 예약, 리마인드, 과정연계, 결과물 품질로 참여율을 높인다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “AI서비스 과정 120명 → 취업가능 직무 6개 → 수요 확인기업 42개 → TO 68명 → 추천동의 35개사 → 면접 90건 → 최종입사 32명. 기업별 담당자·수요확인일·채용시기는 부록 E-31에 제시한다.”

**나쁜 예시**: “전국 5만 개 회원사 DB와 온라인 홍보를 활용해 우수기업을 발굴한다.”

**좋은 예시**: “서류진단 루브릭으로 포트폴리오 완성도를 사전·사후 평가하고, 직무별 현직자 12명이 2회 첨삭 후 제출 가능 상태를 승인한다.”

**나쁜 예시**: “유명 대기업 인사담당자를 섭외하고 경품 이벤트로 참여를 독려한다.”

### 실무 적용 포인트

- [ ] 8개 캠퍼스 모든 교육과정과 취업가능 직무를 매핑했는가?
- [ ] 기업별 실제 채용수요와 예상 TO, 시기, 고용형태를 확인했는가?
- [ ] 채용수요 확인일과 확인자를 내부적으로 관리하는가?
- [ ] 기업 접촉 → 수요 확인 → 추천 → 면접 → 채용 → 증빙 프로세스가 있는가?
- [ ] 주 1회 맞춤 채용정보, 월 30건 면접 연계가 일정·인력에 반영됐는가?
- [ ] 통합·캠퍼스 매칭데이의 기업확보, 서류전형, 매칭, 현장, 사후관리 전 과정이 있는가?
- [ ] 발굴기업·TO·면접·최종입사 KPI를 각각 제시했는가?
- [ ] 양질의 일자리 기준을 정규직 여부, 처우, 직무적합성 등으로 정의했는가?
- [ ] 1:1 프로그램 전문가가 실제 가용하며 잡코디와 역할이 분리됐는가?
- [ ] 프로그램 참여율과 결과물 품질을 높일 방안이 있는가?

### 증빙자료 기준

- 기업명단만으로 부족하다. `기업명 / 사업자정보 / 직무 / TO / 고용형태 / 근무지 / 채용시기 / 수요확인일 / 확인방법 / 담당자 / 연계상태`를 갖춘다.
- 개인정보와 영업비밀은 마스킹하되 평가에 필요한 사실은 식별 가능해야 한다.
- 전문가 이력, 최근 유사 첨삭 결과, 참여의향, 가능시간을 함께 제시한다.
- 네트워크 활용사례는 모집 홍보가 아니라 실제 면접·채용 결과로 증명한다.

### PT/Q&A 연결 포인트

- PT에서는 캠퍼스 1곳을 골라 과정 → 직무 → 기업 → TO → 면접 → 입사의 실제 예시를 보여준다.
- 예상 질문: “지금 실제 수요를 확인할 수 있는 기업은 몇 곳입니까?”, “DB와 확정수요를 어떻게 구분했습니까?”, “최종입사 목표가 미달하면 어느 선행지표부터 보완합니까?”
- 기업 수를 과장하지 말고 기준일과 단계별 숫자를 답한다.

## 7. 수행인력 체크 — 정량 6점 + 정성 10점

### 교육목표

평가용 이름이 아니라 실제로 기획·운영·통제할 인력과 조직을 제시하고, 각자의 역량과 투입 가능성을 증명한다.

### 평가위원 관점

정량평가에서 사업운영 전담인력 3명 이상이면 6점, 2명은 4.8점, 1명 이하는 3.6점이다. 전담인력은 참여율 30% 이상이어야 하고 추후 변경할 수 없으며 잡코디는 포함되지 않는다. 정성평가에서는 조직의 적합성, 실질 참여, 기획·관리 담당 배정, 역량을 본다.

PM은 발표자이며 입찰공고일 전부터 제안사에 1년 이상 재직한 정규직이어야 한다. 발표자와 참관자는 제안서상 수행인력이어야 한다.

### 작성원칙

1. 과업 WBS별 책임자와 산출물을 지정한다.
2. 인력별 참여율, 기간, 주요업무, 의사결정 권한을 일치시킨다.
3. PM은 명목상 관리자가 아니라 일정·품질·예산·이슈를 통제하는 사람으로 설계한다.
4. 결원·퇴사·피크기간의 대체인력과 인수인계 기준을 제시한다.
5. 최근 3년 유사경력과 본 과업 역할의 직접 관련성을 설명한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “PM 김OO(참여율 50%)은 최근 3년 청년 취업연계 사업 3건에서 PM을 맡았고, 주간 KPI회의·예산승인·SBA 보고·중대이슈 2시간 내 보고를 책임진다.”

**나쁜 예시**: “대표이사가 총괄하고 다수 전문인력이 지원한다.”

### 실무 적용 포인트

- [ ] 전담인력 3명 이상이 참여율 30% 이상인가?
- [ ] 잡코디를 정량 전담인력 수에 잘못 포함하지 않았는가?
- [ ] PM과 핵심인력이 실제 사업에 참여하는가?
- [ ] 인력별 업무·참여율·일정이 현실적인가?
- [ ] 기획, 기업발굴, 프로그램, 데이터, 보고, 예산 책임자가 분명한가?
- [ ] 공백 시 대체인력과 승인·인수인계 절차가 있는가?
- [ ] 조직도가 보고·의사결정·에스컬레이션 체계를 보여주는가?
- [ ] 발표자와 참관자가 수행인력 명단 및 재직요건을 충족하는가?

### 증빙자료 기준

- 재직증명서, 최종학위증명서, 관련 자격증, 건강보험 또는 근로소득원천징수 자료를 요구 기준에 맞춰 준비한다.
- 최근 3년 참여실적, 참여기간, 담당업무, 발주처를 기재한다.
- 참여인력 이외 재직자의 개인정보 자료는 제출하지 않는다.
- 허위가 확인되면 0점 또는 참가 제외 위험이 있으므로 원본과 제안서 표기를 대조한다.

### PT/Q&A 연결 포인트

- PM이 직접 발표하므로 모든 KPI, 예산, 기업수요, 인력운영을 자기 언어로 설명해야 한다.
- 예상 질문: “PM이 동시에 수행하는 다른 사업은?”, “핵심인력 퇴사 시?”, “30% 참여율로 실제 통제가 가능합니까?”
- 답변은 주간 투입시간, 의사결정 권한, 대체자, 인수인계 기한으로 구체화한다.

## 8. KPI 체크

### 교육목표

활동량이 아니라 취업성과까지 연결되는 Funnel KPI와 조기경보 체계를 만든다.

### 평가위원 관점

평가위원은 목표 숫자의 크기보다 산식, 모수, 기준일, 데이터 출처, 담당자, 관리주기, 미달 시 조치를 본다. 매칭데이는 발굴기업·채용 TO·면접연계·최종입사를 개별적으로 요구한다.

### 작성원칙

모든 핵심과업에 다음 4단계를 둔다.

- **Input**: 투입인력, 가용기업, 전문가, 예산
- **Activity**: 상담, 수요확인, 첨삭, 추천, 행사
- **Output**: 상담완료, 수요기업, TO, 면접, 완성서류
- **Outcome**: 최종입사, 취업률, 유지취업, 양질 일자리 비율

KPI 사전에는 `정의 / 산식 / 분모·분자 / 데이터 원천 / 기준일 / 목표 / 주기 / 책임자 / 경보선 / 개선조치`를 기록한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “취업률 = 기준일 현재 취업증빙이 완료된 취업자 ÷ RFP 기준 취업대상자 × 100. 매주 갱신하며 목표경로 대비 -5%p이면 PM이 과정별 회복계획을 2영업일 내 제출한다.”

**나쁜 예시**: “기업 100개 발굴, 취업률 최대화.”

### 실무 적용 포인트

- [ ] 기업발굴 → 수요확인 → TO → 추천 → 면접 → 최종입사 Funnel이 있는가?
- [ ] 캠퍼스·과정·월별로 분해할 수 있는가?
- [ ] 80% 취업률의 분모·분자와 기준일이 명확한가?
- [ ] 중복 기업·중복 면접·취소 건 처리규칙이 있는가?
- [ ] 정규직 등 양질의 일자리 지표가 있는가?
- [ ] 목표 미달을 사전에 알리는 선행지표와 경보선이 있는가?
- [ ] KPI가 일정·인력·예산과 연결되는가?

### 증빙자료 기준

KPI마다 원천데이터와 증빙상태를 연결한다. 면접은 일정확정 또는 기업확인, 입사는 재직·고용 등 RFP가 인정하는 자료로 검증한다. 개인정보 접근권한, 보존기간, 파기절차도 정한다.

### PT/Q&A 연결 포인트

- PT에서는 Funnel 한 장과 목표 미달 시 회복 시나리오 한 장을 준비한다.
- 예상 질문: “면접연계 120건이 취업 45명으로 이어진다는 근거는?”, “취업률 분모는 누구입니까?”
- 답변은 과거 전환율, 이번 목표 전환율, 보수적 가정으로 설명한다.

## 9. Evidence 체크

### 교육목표

모든 핵심 주장을 객관적 자료와 연결하고, 제출 형식·유효기간·날인·페이지를 검증한다.

### 평가위원 관점

근거가 없으면 해당 사항이 없는 것으로 간주된다. 평가위원은 자료의 존재뿐 아니라 주장과의 직접성, 최신성, 발급주체, 원본성, 범위, 수치 일치 여부를 본다.

### 작성원칙

1. 한 주장에 하나의 Evidence ID를 부여한다.
2. 본문에 부록 페이지를 명시한다.
3. 원본·원본대조필·날인·유효기간 요구를 확인한다.
4. 과장하거나 다른 범위의 실적을 같은 것으로 표현하지 않는다.
5. 개인정보와 기업 영업비밀을 최소수집·마스킹한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “최근 3년 유사사업 6건(단일 계약 2억원 이상, 완료 기준) — 실적증명서 E-01~E-06, 계약서·세금계산서 E-07~E-18.”

**나쁜 예시**: “다수 유사사업 수행”이라고 쓰고 회사 홍보 브로슈어만 첨부한다.

### 실무 적용 포인트

- [ ] 계약서, 실적증명서, 발주기관 확인자료가 있는가?
- [ ] 운영결과, 성과보고서, 참여자·취업 데이터가 있는가?
- [ ] 기업명단과 실제 채용수요 확인자료가 있는가?
- [ ] 전문가 이력과 참여가능 증빙이 있는가?
- [ ] 시스템 화면, 매뉴얼, 운영사진, 만족도·성과분석이 있는가?
- [ ] 본문 수치와 증빙 수치가 일치하는가?
- [ ] 모든 증빙에 ID와 페이지가 있는가?

### 증빙자료 기준

- 최근 3년 유사실적 정량 인정기준은 청년(만 19~39세) 또는 대학생 대상 취업·구직 지원 또는 청년-기업 연계 활동, 완료 용역, 단일 계약 2억원 이상이다.
- 나라장터 외 공공·민간 실적은 지정 실적서식, 세금계산서, 계약서 또는 협약서를 모두 준비한다.
- 신용평가 확인서는 공고일 이전 평가, 유효기간 내, 가장 최근 등급을 사용한다. 미제출 시 최하점이다.
- 기술평가 당일 자료 변경·추가 제출은 불가하다.

### PT/Q&A 연결 포인트

- 주요 답변마다 “제안서 p.○○, 증빙 E-○○”를 즉시 안내할 수 있어야 한다.
- 예상 질문: “그 숫자를 확인할 수 있는 자료는 무엇입니까?”, “이 실적이 본 사업과 유사하다는 근거는?”

## 10. 차별화 체크

### 교육목표

경쟁사도 쓸 수 있는 수식어를 제거하고, 실제 자산·프로세스·성과로 차별화를 증명한다.

### 평가위원 관점

차별성은 새로움 자체가 아니라 평가항목의 성과를 더 확실하게 만드는가로 판단한다. AI·플랫폼도 취업률, 상담품질, 매칭속도, 증빙정확성을 개선할 때 의미가 있다.

### 작성원칙

- 차별점마다 `비교기준 / 우리 방식 / 실행자산 / 측정효과 / Evidence`를 둔다.
- 경쟁사 이름이나 확인 불가능한 우월 주장을 피한다.
- 예산과 일정 내 실행 가능하며 계약상 수행할 수 있는 것만 쓴다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “상담 미완료 위험을 주간 자동 탐지해 잡코디에게 후속과제를 배정하며, 유사사업에서 7일 초과 미접촉 비율을 18%에서 4%로 낮췄다.”

**나쁜 예시**: “업계 최초 AI 기반 최고의 플랫폼을 활용한다.”

### 실무 적용 포인트

- [ ] 경쟁사도 그대로 쓸 수 있는 표현을 제거했는가?
- [ ] 실적·인력·기업수요·프로세스 중 고유 자산이 있는가?
- [ ] 차별화가 25점·15점 등 핵심 항목과 직접 연결되는가?
- [ ] AI 사용보다 성과개선과 책임 있는 운영을 설명했는가?
- [ ] 일정과 예산에 반영했는가?

### 증빙자료 기준

기존 운영화면, 전후 성과, 고객 확인자료, 매뉴얼, 실제 사용자와 운영조직으로 증명한다. 시제품은 운영 중인 시스템으로 오인하게 표현하지 않는다.

### PT/Q&A 연결 포인트

- 예상 질문: “경쟁사도 같은 말을 할 수 있는데 귀사만 가능한 근거는?”, “이 기능이 취업률을 얼마나 개선합니까?”
- 한 문장 차별화는 반드시 수치와 증빙으로 이어져야 한다.

## 11. 페이지별 검수

### 교육목표

모든 페이지가 평가질문 하나에 빠르게 답하고, 내용·수치·증빙·형식 오류 없이 제출되도록 한다.

### 평가위원 관점

평가위원은 짧은 시간에 페이지 제목, 핵심 숫자, 도표, 근거를 훑는다. 제목이 주제어에 그치거나 한 페이지에 여러 결론이 섞이면 이해와 점수화가 늦어진다.

### 작성원칙 — 평가위원 5초 테스트

- [ ] 5초 안에 이 페이지의 결론을 알 수 있는가?
- [ ] 제목만 읽어도 주장과 기대성과가 보이는가?
- [ ] 평가항목과 관계없는 내용은 없는가?
- [ ] 핵심 숫자와 비교기준이 보이는가?
- [ ] 차별점과 근거가 보이는가?
- [ ] 사업성과로 어떻게 이어지는지 보이는가?
- [ ] 주장 하나에 시각자료 하나, Evidence 하나가 연결되는가?

### 좋은 예시 / 나쁜 예시

**좋은 제목**: “과정별 실수요기업 42개를 수료 8주 전 확보해 면접 공백을 제거합니다.”

**나쁜 제목**: “3.2 기업 네트워크 운영방안.”

### 실무 적용 포인트

- 내용 검수자, 숫자 검수자, RFP 준수 검수자, 편집 검수자를 분리한다.
- 역방향으로 `증빙 → 본문 주장 → 평가항목`을 점검한다.
- 표지 포함 제안서 50쪽, PT 30쪽 제한을 확인한다.
- 제안서 목차를 별도 작성하고 본문에서 증빙 페이지를 기재한다.
- 원본 외 모든 자료에서 회사명·로고·실적 속 식별정보 등 제안업체 식별정보를 제거한다.
- 제안서와 PT의 숫자·용어·인력·일정·예산을 대조한다.
- PT와 제안서는 제출 후 임의 변경할 수 없으므로 최종본 해시와 버전을 잠근다.

### 증빙자료 기준

최종 검수표에 `페이지 / 평가항목 / 핵심주장 / 숫자 출처 / Evidence ID / 익명성 / 검수자 / 상태`를 기록한다. 날인 누락은 평가 제외로 이어질 수 있으므로 원본 서류별 날인 여부를 별도 확인한다.

### PT/Q&A 연결 포인트

- 10분 발표를 최소 3회 실측하고 초과하지 않는다.
- 회사 식별 표식·발언을 금지하고, 시간 초과 후 발표하지 않는다.
- 발표자·참관자의 신분증과 재직증명서를 준비한다.
- 구두 발표와 답변도 제안내용의 일부가 되므로 제안서 밖의 새 약속을 하지 않는다.

## 12. 최종 평가위원 Self-Scoring

### 교육목표

제출팀의 자신감이 아니라 평가표와 Evidence를 기준으로 점수를 산출하고, 재작성 우선순위를 결정한다.

### 평가위원 관점

정성항목은 A~E 등급으로 평가된다.

| 평가항목 | 배점 | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|---:|
| 과업이해도 | 10 | 10 | 9 | 8 | 7 | 6 |
| 잡코디 운영 | 15 | 15 | 13.5 | 12 | 10.5 | 9 |
| 채용기업 발굴·취업지원 | 25 | 25 | 22.5 | 20 | 17.5 | 15 |
| 수행인력 | 10 | 10 | 9 | 8 | 7 | 6 |
| 관리능력 | 10 | 10 | 9 | 8 | 7 | 6 |

### 작성원칙

- **A**: 구체성·실현가능성·차별성·성과수치·Evidence가 모두 있어 즉시 최고점을 줄 수 있음.
- **B**: 좋은 제안이나 일부 근거 또는 실행 세부가 부족함.
- **C**: 요구는 충족하지만 일반적이고 경쟁사 대비 차별성이 약함.
- **D**: 추상적이며 실행 가능성과 성과 연결을 확인하기 어려움.
- **E**: 요구사항 일부를 충족하지 못하거나 근거가 없음.

Self-Scoring은 최소 2명이 독립 채점하고, 1등급 이상 차이가 나면 근거 페이지를 놓고 조정한다. 내부 원칙은 **C 이하 항목이 하나라도 있으면 제출 전에 재작성**하는 것이다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “기업발굴 항목 B(22.5점). 프로세스와 KPI는 A 수준이나 실제 수요확인 기업 12곳의 최신 확인자료가 부족해 B로 판정. 보완 책임자와 마감일 지정.”

**나쁜 예시**: “내용이 좋아 보이므로 전 항목 A.”

### 실무 적용 포인트

- [ ] 평가질문별 근거 페이지를 표시해 채점했는가?
- [ ] 정량점수 20점을 증빙기준대로 다시 계산했는가?
- [ ] 정성 70점을 공식 A~E 점수로 계산했는가?
- [ ] 가격 10점을 포함한 예상 총점을 계산했는가?
- [ ] 협상 적격 기준 총점 70점 이상을 충족하는가?
- [ ] 최고 배점 25점·15점 항목의 하락 요인을 먼저 보완했는가?
- [ ] 근거 없는 A 등급을 금지했는가?
- [ ] Red Team이 예상 질문과 반증을 제시했는가?

### 증빙자료 기준

자가평가표에는 `평가질문 / 등급 / 점수 / 근거 페이지 / Evidence ID / 결함 / 보완조치 / 책임자 / 마감`을 기록한다. 정량평가의 자기점수가 잘못되어도 발주기관 점수가 적용되므로 산식과 증빙을 이중 검수한다.

### PT/Q&A 연결 포인트

- Self-Scoring에서 B 이하인 항목은 Q&A 고위험 목록으로 자동 전환한다.
- 모의평가는 평가위원 역할, PM, 기록자, 사실확인자로 나누어 15분 질의응답을 실측한다.
- 답변은 40초 내 `결론 → 근거 숫자 → 실행방법 → 문서 위치`로 마무리한다.

## 부록 A. 과업관리능력 교육 모듈 — 10점

### 교육목표

캠퍼스별 교육기간과 집중 취업지원기간을 반영해 일정·예산·보고·리스크를 통제한다.

### 평가위원 관점

평가위원은 캠퍼스별 관리와 예산의 타당성, 발주부서·교육파트너·캠퍼스와의 커뮤니케이션, 현장 돌발변수 대응능력을 본다.

### 작성원칙

- 착수부터 결과보고까지 보고 종류, 주기, 제출자, 승인자를 정한다.
- 정기보고와 수시보고를 구분하고 중대이슈의 등급과 보고기한을 정한다.
- 일정은 캠퍼스 교육·수료·집중취업지원 시기와 연결한다.
- 예산은 WBS·KPI·산출물과 연결하고 일반관리비·이윤 등 견적 기준을 준수한다.
- 매칭데이는 별도 상세 일정으로 관리하되 KPI에 발굴기업·TO·면접·입사를 포함한다.

### 좋은 예시 / 나쁜 예시

**좋은 예시**: “취업률 목표경로 -5%p, 개인정보 사고, 행사 취소는 Red 이슈로 분류해 2시간 내 SBA에 1차 보고하고 24시간 내 조치계획을 제출한다.”

**나쁜 예시**: “발주처와 긴밀히 협의하며 돌발상황에 유연하게 대응한다.”

### 실무 적용 포인트

- [ ] 주간·월간·수시·중대이슈 보고체계가 있는가?
- [ ] 캠퍼스별 일정과 인력 피크가 반영됐는가?
- [ ] RACI와 의사결정·승인 기한이 있는가?
- [ ] 리스크 등록부와 에스컬레이션 기준이 있는가?
- [ ] 예산 항목이 과업·KPI·산출물과 일치하는가?
- [ ] 변경관리와 버전관리 절차가 있는가?

### 증빙자료 기준

통합 일정표, RACI, 보고서 견본, 회의체 운영안, 리스크 등록부, 비상연락망, 예산 산출근거를 첨부한다.

### PT/Q&A 연결 포인트

- 예상 질문: “캠퍼스 요청과 본부 지시가 충돌하면?”, “예산 초과나 일정 지연은 언제 보고합니까?”
- 권한, 판단기준, 보고기한, 대안을 답한다.

## 부록 B. 제출 전 최종 Gate

### Gate 1 — 내용 완결성

- [ ] 모든 평가질문에 직접 답하는 페이지가 있다.
- [ ] 주장마다 실행자·일정·KPI·Evidence가 있다.
- [ ] 과업이해도, 잡코디, 기업발굴, 수행인력, 관리능력의 수치가 서로 연결된다.

### Gate 2 — 사실·증빙

- [ ] 실적, 재직, 신용등급, 기업수요, 전문가 가용성을 기준일 현재 확인했다.
- [ ] 본문과 부록의 수치·명칭·기간이 일치한다.
- [ ] 필요한 원본, 원본대조필, 대표자 날인, 세금계산서, 계약서가 갖춰졌다.

### Gate 3 — 형식·익명성

- [ ] 제안서 50쪽, PT 30쪽 이내이며 표지를 포함해 계산했다.
- [ ] 별도 목차와 증빙 페이지 안내가 있다.
- [ ] 사본에서 업체 식별정보를 모두 삭제했다.
- [ ] 출력 부수, USB, 파일형식, 제본, 서류 순서를 확인했다.

### Gate 4 — PT/Q&A

- [ ] PM 자격과 수행인력 등록을 확인했다.
- [ ] 10분 발표와 15분 Q&A를 실측했다.
- [ ] 발표자·참관자 신분증과 재직증명서를 준비했다.
- [ ] 회사 식별 발언·표식과 제안서 밖의 약속을 제거했다.

### Gate 5 — 최종 승인

- [ ] 작성자, 평가항목 오너, Evidence 담당, PM, 최종 승인자가 서명했다.
- [ ] C 이하 항목이 없거나 최고책임자가 잔여위험을 승인했다.
- [ ] 제출본과 보관본의 버전·파일명을 잠그고 최종본을 대조했다.

## 교육 운영 권장안

1. **RFP 해체 실습(60분)**: 요구사항 추적표와 평가질문 추출
2. **배점별 작성 실습(120분)**: 25점 기업발굴, 15점 잡코디를 우선 작성
3. **Evidence Clinic(60분)**: 주장과 증빙의 직접성·유효성 검수
4. **페이지 5초 테스트(45분)**: 결론형 제목과 숫자·도표 교정
5. **독립 Self-Scoring(45분)**: 공식 A~E 점수 적용
6. **PM 모의 PT/Q&A(40분)**: 10분 발표, 15분 질의, 15분 피드백

교육의 최종 산출물은 강의 수료증이 아니라 `요구사항 추적표`, `평가항목별 원고`, `Evidence Map`, `KPI 사전`, `Self-Scoring Sheet`, `PT/Q&A 답변집`, `최종 Gate 서명본`이어야 한다.
