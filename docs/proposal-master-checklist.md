# 사업수주형 제안서 작성 Master Checklist

### 목적: “작성 완료”가 아니라 “평가위원이 점수를 줄 수 있는 상태”를 확인한다.

## 1. RFP 분석 단계

- [ ] 사업의 **최종 정책목표/성과목표**를 한 문장으로 정의했는가?
- [ ] 발주기관이 해결하려는 핵심 문제를 3개 이내로 정리했는가?
- [ ] 정량평가/정성평가/가격평가의 배점을 분리했는가?
- [ ] 정성평가 항목을 **배점 높은 순서**로 재정렬했는가?
- [ ] 평가항목별 세부 평가질문을 모두 추출했는가?
- [ ] RFP의 `중요`, `필수`, `반드시`, `불가`, `제외` 표현을 별도로 추출했는가?
- [ ] 과업지시서와 제안요청서의 요구사항을 Cross Check 했는가?
- [ ] 평가항목에는 없지만 반드시 수행해야 할 과업을 구분했는가?
- [ ] 제안 불가사항과 감점·실격요인을 별도로 정리했는가?
- [ ] 페이지 수, 파일형식, 익명처리, 날인 등 형식요건을 확인했는가?

# 2. 평가항목 → 제안서 매핑

각 평가항목마다 아래 7가지를 반드시 작성한다.

- [ ] ① 평가위원이 확인하려는 것은 무엇인가?
- [ ] ② 발주기관이 가지고 있는 문제는 무엇인가?
- [ ] ③ 우리 회사의 해결방법은 무엇인가?
- [ ] ④ 경쟁사와 다른 방법은 무엇인가?
- [ ] ⑤ 실행 프로세스는 구체적인가?
- [ ] ⑥ KPI/수치로 성과를 표현했는가?
- [ ] ⑦ 이를 입증할 Evidence가 있는가?

**원칙**

> 주장 → 방법 → 담당자 → 일정 → KPI → 증빙

6개 중 하나라도 없으면 “좋은 아이디어”일 수는 있어도 “고득점 제안”으로 판단하지 않는다.

# 3. 과업 이해도 체크

- [ ] 사업 목적을 단순히 RFP에서 복사하지 않고 **발주기관 관점의 문제**로 해석했는가?
- [ ] 사업대상자의 특성을 분석했는가?
- [ ] 사업 수행지역/캠퍼스/기관별 차이를 분석했는가?
- [ ] 전년도 또는 기존 사업의 문제점을 분석했는가?
- [ ] 목표성과 달성을 방해하는 핵심 Bottleneck을 제시했는가?
- [ ] 그 Bottleneck과 제안전략이 직접 연결되는가?
- [ ] 사업목표 → 추진전략 → 세부과업 → KPI가 한 줄로 연결되는가?
- [ ] 제안사의 장점 설명보다 **이 사업에서 왜 필요한지**를 먼저 설명했는가?

# 4. 실행계획 체크

- [ ] “강화한다”, “활성화한다”, “적극 추진한다” 수준에서 끝나지 않는가?
- [ ] 누가(Who) 수행하는지 제시했는가?
- [ ] 언제(When) 수행하는지 제시했는가?
- [ ] 어떤 절차(How)로 수행하는지 제시했는가?
- [ ] 몇 건/몇 명/몇 회인지 수치가 있는가?
- [ ] 결과를 어떤 데이터로 관리하는지 제시했는가?
- [ ] 목표 미달 시 대응 프로세스가 있는가?
- [ ] 돌발상황 발생 시 Escalation 체계를 제시했는가?

# 5. 실현가능성 체크

- [ ] 실제 보유하지 않은 자원이나 인력을 제안하고 있지 않은가?
- [ ] 협력 예정 기업·전문가의 실제 투입 가능성을 확인했는가?
- [ ] “협의 예정”, “확보 예정”, “가능할 것으로 판단” 표현을 최소화했는가?
- [ ] 과거 수행사례가 있는 경우 결과수치까지 제시했는가?
- [ ] 신규 아이디어라면 실행방법·담당자·예산·일정·KPI가 있는가?
- [ ] 과업기간과 예산 내 실제 실행 가능한 수준인가?

# 6. 기업·기관 네트워크 제안 체크

- [ ] “OO개 기업 DB 보유”만 제시하고 있지 않은가?
- [ ] 실제 활용 가능한 기업을 구분했는가?
- [ ] 기업별 채용직무를 파악했는가?
- [ ] 예상 채용 TO를 확인했는가?
- [ ] 대상 교육과정과 기업 직무를 Matching 했는가?
- [ ] 기업 접촉 → 채용수요 확인 → 구직자 추천 → 면접 → 채용까지 프로세스가 있는가?
- [ ] 기업 담당자 또는 접촉 근거를 내부적으로 확보했는가?
- [ ] 기존 네트워크 활용 실적을 증명할 자료가 있는가?

### 금지 표현

“전국 기업 네트워크를 활용한다.”

### 권장 구조

“OO분야 00개 기업 → 실제 채용수요 확인기업 00개 → 예상 TO 00명 → 교육과정 A/B/C와 연계 → 월 00건 면접 → 최종 00명 취업 목표”

# 7. 수행인력 체크

- [ ] PM이 명목상 PM이 아니라 실제 사업을 관리할 수 있는가?
- [ ] PM 경력이 해당 사업과 직접 관련되는가?
- [ ] 핵심과업별 책임자가 지정되어 있는가?
- [ ] 제안서에 등장한 사람이 실제 사업에 참여하는가?
- [ ] 투입률과 수행업무가 현실적인가?
- [ ] 인력 공백 발생 시 대체인력 계획이 있는가?
- [ ] 수행인력의 경력을 증빙할 수 있는가?
- [ ] 조직도가 단순 조직소개가 아니라 의사결정·보고체계를 보여주는가?

# 8. KPI 체크

모든 핵심과업에 최소 다음 구조가 있는지 확인한다.

- [ ] Input KPI
- [ ] Activity KPI
- [ ] Output KPI
- [ ] Outcome KPI

예:

기업발굴 100개  
→ 채용수요 확인 50개  
→ 채용 TO 80명  
→ 면접연계 120건  
→ 최종취업 45명

단순한 “기업 100개 발굴”보다 **최종 사업성과까지 이어지는 Funnel KPI**를 제시한다.

# 9. Evidence 체크

모든 핵심 주장 옆에 다음 중 최소 하나가 있는가?

- [ ] 계약서
- [ ] 실적증명서
- [ ] 발주기관 확인자료
- [ ] 실제 운영 결과
- [ ] 성과보고서
- [ ] 참여자 데이터
- [ ] 취업성과
- [ ] 기업명단
- [ ] 채용수요
- [ ] 전문가 이력
- [ ] 협약/협력 증빙
- [ ] 시스템 화면
- [ ] 프로그램 운영사진
- [ ] 만족도/성과분석

### 내부 작성원칙

**Evidence 없는 강점은 제안서에서 강점으로 인정하지 않는다.**

# 10. 차별화 체크

- [ ] 경쟁사도 그대로 쓸 수 있는 표현을 사용하고 있지 않은가?
- [ ] 우리 회사만의 실제 실적·인력·DB·프로세스가 들어갔는가?
- [ ] 차별화 요소가 평가항목과 직접 연결되는가?
- [ ] 새로운 기술이나 AI를 제안할 경우 “AI 사용”이 아니라 사업성과 개선과 연결했는가?
- [ ] 차별화가 예산과 일정 안에서 실행 가능한가?

# 11. 페이지별 검수

모든 페이지에 다음 질문을 한다.

### 평가위원 5초 테스트

- [ ] 이 페이지가 무슨 말을 하는지 5초 안에 알 수 있는가?
- [ ] 제목만 읽어도 결론이 보이는가?
- [ ] 평가항목과 관계없는 내용은 없는가?
- [ ] 핵심 숫자가 보이는가?
- [ ] 경쟁사와 다른 부분이 보이는가?
- [ ] 근거가 보이는가?
- [ ] “그래서 사업성과가 어떻게 좋아지는지” 보이는가?

# 12. 최종 평가위원 Self-Scoring

각 평가항목을 5단계로 평가한다.

**A — 즉시 최고점 부여 가능**

- 구체성
- 실현가능성
- 차별성
- 성과수치
- Evidence 모두 확보

**B — 좋은 제안이나 일부 근거 부족**

**C — 일반적인 수준, 경쟁사와 차별성 부족**

**D — 추상적이며 실행 가능성 확인 어려움**

**E — RFP 요구사항을 충족하지 못함**

### 내부 원칙

**C 이하 항목이 하나라도 있으면 제출 전에 재작성한다.**
